结论先行

这是对该项目的第二轮全量审查。上一轮《隐蔽性与效率优化建议》审查的是 4,453 行的版本；此后唯一一次功能提交（列表滚动轮播、按分组记忆排序、个股股价提醒、接口风控应对）把代码量推到了约 7,200 行。本轮通读全部源码并交叉验证，重点回答三件事：新代码引入了什么问题、上轮建议落地了多少、代码本身需要如何整理。

总体判断

骨架是健康的，且「效率」侧在上轮审查后补强明显：东财主源的同轮快重试、备源滞回（最短停留 60s + 探活退避 + 观察期）、分时双源兜底都有针对性单测覆盖（测试总数 43 → 60，全部通过）。分层（core 零 Electron 依赖 / 渲染层零网络 / IPC 白名单收口 / 原子写存储 + .bak 回滚）是这个代码库最值钱的资产，后续所有改动都应守住。

但上轮 5 项 P0（隐蔽性侧）全部未落地：⌘Tab/Dock 隐身联动、通知静默化、提醒口径修正、指数异动提醒、非交易时段停轮询——一项都没动。最近一次提交是纯功能向的，与上轮建议的优先级方向正好错开。

本轮新发现 9 个真实缺陷：2 项高（美股自选周五晚提醒全灭；备源自身故障时永久卡死回不到主源）、3 项中（渲染层崩溃重建后状态失联；会议模式中按老板键反而弹出窗口；设置窗失焦即藏打断复制粘贴工作流）、4 项低。另有 12 项代码整理与工程化事项，其中最迫切的是把 976 行的 index.js 拆掉。

最值得先做的三件事（合计约半天）：A1 修 usMaybe() 的周末判定、A2 在失败分支补探活调用、A3 把 blur/穿透恢复收进 wireMainWindow()。随后用约一天补齐上轮 P0-1～P0-5（清单见第 2 章，改法在上轮文档里已经写好，此处只核对状态）。

01

新发现缺陷

以下 9 项均为上轮报告未覆盖、本轮通读新代码时发现的真实缺陷，按严重度排列。每项给出影响、根因与修法；行号以当前 commit 为准。A 股纯自选用户几乎不受 A1/A2 影响，但持仓含美股（项目明确支持 105.AAPL 一类 secid）时它们是硬故障。

A1高

美股自选周五晚全程「已收盘」：股价提醒与异动提醒全灭

根因 src/core/session.js:36 usMaybe()，影响 orchestrator 的 phase 判定与全部提醒链路

美股用「北京宽窗口 20:30–05:00」判定交易时段，但入口先做了 if (!isWeekday(d)) return false。北京周六 00:00–05:00 恰好是美股周五晚盘（冬令时到 04:00、夏令时到 05:00），却被周末判断拦下，phase 落到 closed。后果链：checkAlerts() 与 checkPriceRules() 都要求 phase === 'open' || 'auction' 才检查——于是自选里的美股在周五晚上涨破任何阈值都不会提醒，界面状态条也误标「已收盘」，刷新降为 60s 心跳。

这对「异动找你，不用盯」的核心承诺是直接违约：恰恰是美股时段（晚上加班时）最需要提醒的时候，提醒是死的。

function usMaybe(d) {
  const m = minutesOfDay(d);
  if (d.getDay() === 6) return m < 300;   // 周六凌晨 = 美股周五晚盘，放行
  if (!isWeekday(d)) return false;          // 周日（美股休市）维持关闭
  return m >= 1230 || m < 300;
}

修法如上（宽窗口哲学不变，误开由自适应降速兜底，与现有设计一致）。修完应在 tests/run.js 补「周六 01:00 含 US → open」的边界用例——这正是当前测试空白让 bug 溜过去的地方（见 D7）。

A2高

备源自身故障时永久卡死：失败分支没有任何回主源的路径

根因 src/main/orchestrator.js tickQuote() 失败分支；recoverMain() 仅在 L239 成功分支末尾被调用

探活主源的 recoverMain() 只挂在 tickQuote 成功路径的末尾（「备源供数正常时按退避间隔探活」）。一旦切到腾讯后腾讯自己也持续失败，失败分支只有 backoffDelay() 退避重试，永远不会探活东财——哪怕东财早已恢复。用户看到的是永久「网络异常 · 数据为 hh:mm 快照」，只能重启应用。

触发条件并不苛刻：腾讯备源不支持美股（toTencentSymbol 对 105.* 返回 null，整表空响应），而 fetchWithRetry() 把「空 map」判定为失败。自选全部或以美股为主时，东财连续 3 个 tick 撞上坏窗口切备源后，即进入「腾讯永远空响应 → 永远失败 → 永不探活」的死循环。A 股用户因为腾讯能正常供数会走成功分支，不受影响。

修法一行：失败分支末尾补 if (this.source === 'tencent') this.recoverMain(secids).catch(...)；或更彻底——失败时直接对东财做一次 fetchWithRetry 尝试，成功即切回并进入观察期。

A3中

渲染进程崩溃重建后：blur 收弹层失效、穿透状态与实际行为相反、无重建上限

根因 src/main/index.js:897–913 render-process-gone 处理器

  • blur 监听丢失：mainWin.on('blur', …) 是在 main() 里单独挂的，崩溃处理器只重新调用了 wireMainWindow()，重建后的窗口不再响应失焦收弹层（光标监视还在，但行为退化）。
  • 穿透状态反向：穿透开启时崩溃 → 新窗口没有重新 setIgnoreMouseEvents(true)；渲染层 boot 时从 app:boot 拿到 penetrate=true，黄条显示「鼠标穿透中 · ⌥⇧X 恢复」，但窗口实际可点击——提示与事实相反。
  • 无重建上限：若渲染层因脏数据反复崩溃，会无限 destroy → create 循环，窗口闪烁不可用。

修法：把 blur 接线与 penetrate 的重放（mainWin.setIgnoreMouseEvents(penetrate, { forward: true })）都收进 wireMainWindow()；加「60s 内 3 次崩溃则退出并留日志」的熔断。

A4中

会议模式中按老板键 = 把窗口弹回物理屏幕（反向暴露）

根因 src/main/index.js:135 bossAction() 可见性翻转逻辑

会议模式开启时窗口已隐藏。此时按 ⌥⇧H，bossAction() 走「不可见 → showMainWindow()」分支，窗口在物理屏幕上重新出现（防录屏只挡采集与共享，不挡站在旁边的肉眼）。用户的肌肉记忆是「老板来了按老板键」，结果在会议场景下按出来的反而是行情窗。代码里 if (!meetingMode) bossHidden = false 说明作者考虑过状态保持，但翻转显示本身与老板键语义冲突。

修法：bossAction() 入口处 if (meetingMode) return;（保持隐藏；需要看盘时用户应先退会议模式）。

A5中

设置窗失焦即藏，打断「去别处复制 → 回来粘贴」的标准工作流

根因 src/main/window.js createOrShowSettingsWindow() 的 blur 自动隐藏（400ms 保护窗只防打开瞬间的抢焦点）

导入持仓的用法是设置页明确引导的：「粘贴持仓与成本」。真实路径是：打开设置 → 切到券商 App / Excel 复制 → 切回来——切走的瞬间设置窗就藏了，回来得重新从托盘/⌘, 打开（内容还在，但流程被切断）。「从文件导入」同样受影响：文件选择对话框夺走焦点时窗口已隐藏，选完文件回到的是一个看不见的窗口。

这个 blur-hide 的安全收益其实很小：老板键的 hideAuxWindows() 已经覆盖了设置窗的紧急隐藏场景。建议直接移除 blur 自动隐藏，改为显式关闭（⌘W / 关闭按钮）；若保留，至少在「失焦目标是文件对话框」时豁免。

A6低

「仅看置顶」空态文案残留，后续清空列表时提示错误

根因 src/renderer/app.js:534–544 renderRows()

置顶过滤无结果时会改写 #empty .dim 为「眼睛面板 → 关闭『仅看置顶』…」，但恢复默认文案的语句在 if (starOnly) 分支内——只有「过滤开着且有行」才执行。先经历过滤空态、之后清空全部自选时，空态副文案停留在置顶版，误导用户。修法：进入空态分支时无条件重置两句文案。

A7低

多显示器下，股价提醒弹窗被强行钳回主屏

根因 src/main/toast.js:44 clampToScreen() 只用 screen.getPrimaryDisplay()

用户把提醒弹窗拖到副屏记忆位置后，下次弹出会被钳制回主屏底部——副屏办公（外接屏放行情）的场景完全不支持。修法：先 screen.getDisplayMatching({ x, y, width: W, height: H }) 找到目标屏，再按该屏 bounds 钳制；默认位置同理用光标所在屏。

A8低

引导流程选「云端自选」后，第 2 步添加的股票石沉大海

根因 src/renderer/app.js onboarding 步骤 2 与 ipc.js app:list:add（固定写 manualList）

首次引导选云端模式后，第 2 步「添加自选」的搜索与示例组合仍写入 manualList；登录成功后界面显示的是云分组，手动加的票不可见，也没有任何提示。用户会以为添加失败。修法：云端模式下第 2 步改为「去东财 App / 网页加自选即自动同步」的引导说明；或用户在此步实际添加时自动切回手动模式并说明。

A9低

「每日一次」去重键用 UTC 日期，翻转边界在本地 08:00 而非 00:00

根因 src/main/orchestrator.js:380 / 456 new Date().toISOString().slice(0, 10)

北京 00:00–08:00 之间 UTC 日期比本地早一天。核对过现有各交易时段后确认实际影响接近零（A 股盘中、美股整场都不跨这个边界，收盘战报的 15:05 守卫也在窗外），属于语义卫生问题：哪天有人把时段扩到早盘前或夜盘商品，这里会以非常隐蔽的方式漏发。改本地日期一行的事：toLocaleDateString('sv')。

03

功能与体验增量

只列本轮新识别的点；上轮 P1/P2（鼠标热区急隐、悬停变清晰、伪装模式、菜单栏信号档、键盘流扩容等）仍然有效，不在此重复。

3.1emitState 全量广播按签名门控（性能）

tickQuote() 每 5 秒成功都 emitState() 全量 state——「全部合并视图」下（文档提过 422 只）每 tick 都把几百行 × 十几个字段序列化后 IPC 广播给所有窗口，随后渲染层全量 render()。而签名 signature 本来就已经算出来了（目前只用于自适应降速）。改法：签名与上次相同 → 只广播轻量 { status } 补丁，渲染层合并；全量 state 只在签名变化或分组切换时发。同理渲染层可在 document.hidden 时暂存 state、可见时一次性渲染（隐藏窗口期间每 5 秒的 DOM 更新全部是白做功）。

3.2停轮询时的「数据时间」标记（配合上轮 P0-5）

做 P0-5（非交易时段停轮询 / 隐藏暂停）时，菜单栏数字会停在收盘值。建议菜单栏 title 与迷你条在数据超过 N 分钟未更新时追加一个中性符号（如 · 变 :），避免把陈旧数据误读成实时——上轮文档已点出这个坑，这里补一个具体且零暴露的实现位。

3.3持仓金额与汇总：把闲置的 qty 接进 buildRows

上轮 P0-3 的现状表已核实：qty 存了但 buildRows() 不消费。接上后可做三件事：行内副标显示盈亏金额 (price − cost) × qty；持仓分组状态条显示总市值 / 总盈亏 / 总盈亏率；分时图画成本线（cost 已在 rows 里）。金额类信息暴露度高，建议默认关闭、低调与单色模式下强制隐藏（与上轮口径一致）。

3.4量能字段与「放量异动」双确认

请求字段只有价格族（f1–f4/f12–f14/f18），无量能。补 f5（量）/f6（额）后可把异动提醒升级为「价格 + 量能」双确认，明显降噪；行内可加一个量比小标记。上轮 P2-3 已提，此处确认仍未做，且新加的股价提醒同样只有价格维度。

3.5分组切换的键盘档位与「排序中拖拽禁用」提示

非默认排序时禁拖拽已实现，但界面只有标题旁一个 ⇅ 标记；拖拽失败时用户得不到解释。建议 dragstart 被排序拦截时弹一次黄条「排序中，拖拽已禁用（切回默认排序可调整顺序）」。顺带：⌥⇧←/→ 切分组很好用，但窗口内 [ ] 快捷档（上轮 P1-7）仍缺。

04

这一章不改行为、只降复杂度。当前最大的结构性风险：状态散落 + 逻辑副本 + 死代码——三者叠加会让下一次功能提交的成本明显上升。

normSort() 在 renderer/app.js:413 与 main/index.js:580 各有一份，renderer/settings.js 还有第三份内联变体（sortMode === 'pct' ? 'pct-desc' : …）；渲染层 guessMarket() 又与 code-parser 的号段规则重复。根因是「存量值可能不规范」的防御散在读侧。改法：在 Store.set()（或 IPC app:settings:set 入口）做一次 sortMode 归一化，保证落盘值永远规范，然后删掉全部三处读侧副本。guessMarket 若要跨层复用，建一个无 require 的纯 JS 共享文件（渲染层 <script> 可加载、Node 可 require），比复制粘贴耐久。

4.3D3 · 死代码清理（4 处）

  • ipc.js 的 app:list:star handler + preload.js 白名单同名项：无任何调用方（置顶走右键菜单的 ctx.setStar 路径）。
  • constants.js 的 DEMO_LIST：已导出但无人使用；渲染层 addDemo() 硬编码了自己的三只列表，两者还不一致（2 只 vs 3 只）。二者留一。
  • tencent.js 返回的 market / marketNum 字段：无消费方（buildRows 用条目自身的 market），且对北交所会给出错误的 'SZ' 标签——删掉免得将来误用。

4.4D4 · 双 broadcast 实现语义分叉
